# 变更单 CR-1：community 列表「置顶仅第一页返回一次」严格语义

- 出处任务：`kickoff-GHOST-pin-rootfix.md`（G6 / 步骤2）
- 状态：**待签（未实施，零代码改动）**
- 提出：2026-09-15 · 单写者 GHOST 任务
- 关联：`test-reports/GHOST-completion-report.md` §6-①

## 1. 背景

GHOST 任务已根治「同标题重复渲染」表象（脏种子帖软删 40 行 + 分页点序补 `P.id DESC` 全序），
并实证**前批「后端把置顶并入每页分页」的归因不成立**：`list_posts` 只有一条分页 SQL，每条帖子
全局只出现一次（修复前全页扫描 4 轮 `distinct == total == 98`）。

因此现状是「置顶 = 排序优先级」语义，而非 kickoff 字面要求的「置顶只在第一页首屏返回一次」。

## 2. 诉求（需裁决）

是否需要把置顶帖从「排序优先」改为「**只在 page=1 返回**、后续页完全不出现且不计入普通分页」？

## 3. 两种可行实现的代价（二选一，均需签后才动）

| 方案 | 做法 | 影响 | 代价 |
|---|---|---|---|
| **A. 响应新增置顶字段**（推荐） | 响应壳加 `pinned:[PostListItem]`，`items` 只含普通帖，`total` 只计普通帖 | **冻结契约变更**：`PostListResp` 字段变化 → 前端 `community.html`、`edu-frontend/src/lib/api/community*`、`test_contract_task15.py` 需同步 | 契约 diff + 前端改造 + 契约测试更新 + 变更单签署 |
| B. 后续页剔除置顶、`total` 不变 | `page>=2` 的 SQL 加 `AND P.is_pinned=0`，`total` 仍算全量 | 无字段变化，但 **`total` 与 `items` 总数不再自洽** → 直接违反本任务 G4「分页计数正确」 | 语义不自洽，不建议 |

> 方案 B 与 G4 冲突，故实际唯一可行路径是 A，而 A 必改契约结构。

## 4. 不实施的后果（当前状态是否可接受）

- 当前库中**置顶帖仅 1 条**，`page_size` 最小 3 → 置顶恒在 page 1 第 1 位，**用户可见层面已完全正确**。
- 只有在**置顶帖数 > page_size** 时，置顶才会溢到 page 2/3；此时行为是「置顶优先的连续排序」，
  不重复、不漏出、`total/items` 自洽，仅与 kickoff 字面语义有别。
- 维护侧已有防线：`ghost_pin_cleanup.py --check`（同标题重复即 exit 1）+ 3 条 ORDER BY 全序契约测试。

## 5. 建议

**暂不实施**。理由：① 当前无实际可见缺陷；② 变更波及前端 + 冻结契约 + 契约测试，收益仅在
「置顶数超一屏」的极端场景；③ 若确要实施，建议合并进下一次社区域契约批次，单独走 A 方案。

**请编排者裁决**：`签字实施（A）` / `驳回（维持现状）`。
