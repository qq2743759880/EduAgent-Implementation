# EduAgent 前端风格重塑方案 v2.0（黏土拟物版）

> 版本 v2.0（2026-09-20）。v1.0 两项待批已落定：**路线已批 = 静态页原地重塑**；**风格已定 = 黏土拟物（Claymorphism）**。
> 本版吸收外部批判 19 条（高危 6 + 中危 8 + 流程 5）全部对策化（§二总表），门禁从 5 道扩到 **10 道（G1-G10）**，并新增预留接口登记表治理。
> **措辞修正（批判三-1 采纳）**：v1.0 的「功能/接口/交互零损失」改为——**「门禁覆盖范围内零回归 + UAT 签字」**。十道机检门 + UAT 人工回归是工程上能给出的最强保证，但它证明的是「低概率破坏被拦截」，不是数学意义的零损失。
> 环境：前端 3322 / 后端 9988（2026-09-20 端口迁移后，旧 3000/8000 已弃用）。

## 一、路线与承诺（措辞修正版）

| 维度 | 未 React 化（现状 fe-html） | React 化（Next.js） |
|---|---|---|
| 改样式 | 直接改 CSS，所见即所得 | 改组件库主题，需懂组件结构 |
| 结论 | **短期演示/重塑风格：静态页原地改最快最稳（已批）** | 长期按域渐进迁移（既定路线不变） |

## 三、安全架构：十道门禁

### 3.1 CSS-JS 耦合防线（批判一-1 对策）

**CSS 禁改黑名单**（任何页面任何情况下不得改）：

1. JS 测量依赖元素的 `display / height / max-height / position / overflow`——开工前从每页 JS 提取 `offsetWidth / scrollHeight / getBoundingClientRect / clientHeight` 涉及元素清单，冻结其布局属性
2. 状态类 `.active / .hidden / .open / .show / .loading / .disabled` 的**显隐语义**——样式细节可改（如 active 态换珊瑚色），但 `display:none↔block` 的语义结构禁动
3. `pointer-events` 任何改动禁止（防点击穿透/失效）
4. `z-index` 层级表冻结：每页提取现存弹窗/遮罩/下拉/toast 的 z-index 值形成**层级表落档**，重塑后逐项断言不变（防遮挡错位）
5. 结构性选择器 `:nth-child / 父子 / 相邻选择器` 依赖的 DOM 顺序——结构层本来就禁动，此处是双重校验
6. 聊天输入区、HITL 确认卡、视频播放器的容器裁切（`overflow/clip`）——涉及功能可用性，只许换肤不许换几何

## 四、theme.css 治理（防全局单点，批判一-3 对策）

1. **两级分权**：
   - L2 全局 token（§7.1 冻结稿的 ~40 个变量）：改动走**独立 commit**，触发**全 19 页 PARITY + G5/G6 抽查**——把「改一变量 19 页同变」从隐性风险变成显性流程
   - L1 页内私有变量：包在 `.page-<name> { --xxx }` 命名空间里，单页 commit 单页回滚互不牵连
2. **版本与缓存**：所有页引用 `theme.css?v=<commit8>`；G8 断言全站同版本——杜绝「旧 HTML + 新 CSS」混搭
3. **公共组件类**（clay-card / clay-btn 等，§7.3）属 L2，与 token 同级管理
4. 单页回滚时若涉及 L2 变更，回滚手册规定**必须连带评估**（G10 演练覆盖此场景）

## 五、预留接口登记表（批判一-4 对策）

新建 `docs/reserved-api-registry.md`，六字段一行：

```
| endpoint | status(planned/building/live) | contract-link | owner | G1-whitelist | remove-condition |
```

- **G1 规则**：页面出现未登记的 `data-api` → 门禁红；登记而 status≠live 的 → 必须走 §12 四态占位组件渲染，禁止假数据
- 初版登记：`/api/courseware/list`、`/api/assignment/list`、`/api/exam/list`（课程详情三入口）、管理端订单/营收/热门榜聚合端点、用户学习情况弹窗、RAG collections 操作
- **移除条件**：端点 live 且 G1 验证通过后从 whitelist 移入正常契约面；或功能下线时删除 data-api 与登记行

## 七、黏土拟物风格规范（设计令牌冻结稿）

### 7.1 令牌总表（theme.css，L2 级）

**配色**（粉彩基底 + 单屏一个饱和 CTA；色值取自 claymorphism 公开配方，无版权问题）：

```css
:root {
  /* 底色 */
  --bg-app: #F7F5FB;          /* 微紫近白，禁纯 #FFF */
  --bg-raised: #FFFFFF;       /* 仅浮层/弹窗用 */
  /* 六个黏土表面色（卡片/模块用） */
  --clay-lavender: #B8A6FF;   /* 主表面：AI/通用 */
  --clay-sky:      #9EC9F0;   /* 课程/学习 */
  --clay-mint:     #7DD4A8;   /* 完成/正确/进度 */
  --clay-peach:    #FFB59E;   /* 练习/测验 */
  --clay-pink:     #F5B8D0;   /* 收藏/社区 */
  --clay-lemon:    #F5D77A;   /* 待办/提醒 */
  /* 行动与状态 */
  --cta-coral:     #FF7A6B;   /* 每屏唯一饱和 CTA */
  --status-active:   #7DD4A8;
  --status-pending:  #F5D77A;
  --status-archived: #C9B5FF;
  /* 文字（禁纯黑） */
  --text-strong: #2E2A3F;
  --text-muted:  #6B6580;
}
```

> CTA 文字色已定稿（Gate A 实测）：**#2E2A3F 对珊瑚底 = 5.43:1 过 AA**（白字不过对比度门，预判命中）；主表面色按用户批款调整：**lavender 紫降级，主表面换绿系（浅苔绿/抹茶区间，具体 hex 由 THEME-GATE 做对比度校验后冻结），lemon 黄为暖点缀**。

**圆角**（黏土感下限 16px，低于此退化为普通投影卡片）：

```css
--radius-card: 28px;  --radius-btn: 18px;  --radius-input: 16px;
--radius-pill: 999px; --radius-icon-tile: 20px;
```

**阴影三层配方**（光源自左上；**阴影色必须继承表面色相**，灰色阴影会杀死「捏出来的」质感——每个表面色配一档阴影 token）：

```css
/* 以 lavender 为例，其余表面色同构换 hue */
--clay-shadow-lavender:
  8px 8px 24px rgba(122,100,220,.35),          /* 外投影：右下 */
  inset -6px -6px 16px rgba(122,100,220,.25),  /* 内阴影：右下暗部 */
  inset 6px 6px 16px rgba(255,255,255,.55);    /* 内高光：左上 */
--clay-shadow-hover: /* hover 态 */ translateY(-2px) 同配方;
--clay-shadow-press: /* 按下 squish */ scale(.97) 且三层偏移全减半;
```

**间距与尺寸**：8pt 网格（4/8/12/16/24/32/48）；黏土元素相邻最小间距 16px（太挤会糊成一块）；点按区 ≥44×44px（与 G7 一致）；主按钮高 52-56px。

**层级**：L0 平面无影（页面底/表格数据区）→ L1 全配方（卡片/按钮）→ L2 浮层（弹窗/toast：外投影 12px 32px）。**禁止超过 L2**——多层黏土堆叠会糊。

### 7.2 中文字体策略（离线优先）

- 拉丁字符与数字：**Nunito**（开源，woff2 自托管 `public/assets/fonts/`，仅 latin 子集 ~30KB）
- 中文：系统字体栈（`"PingFang SC", "Microsoft YaHei", sans-serif`）——CJK web font 体积不可行，黏土感靠圆角/阴影/配色承载而非字形
- fallback 断言进 G8（模拟 woff2 加载失败不乱版）

### 7.3 组件规范 → 现有元素映射（19 页通吃）

| 现有元素 | clay 类 | 规范要点 |
|---|---|---|
| 课程卡/功能卡/统计卡 | `.clay-card` | 表面色按业务域选（见 7.1 注释），28px 圆角，全配方阴影，**无内边框** |

### 7.4 双密度策略（学生端 vs 管理端）

风格库对 Claymorphism 的 fit/avoid 判定明确写着：**适合教育/儿童/游戏化；不适合 data-critical 数据密集场景**（styles.csv #9 + setproduct 配方同告）。照搬全黏土到管理端表格会牺牲可读性。策略：

- **学生端 13 页 + chat：全黏土**（L1 全配方、粉彩表面、squish 动效）
- **管理端 5 页：clay-light**——页面框架（侧栏/顶栏/统计卡/操作按钮/筛选 chips）用黏土令牌；**数据表格/图表/长列表区降 L0 平面**（仅容器卡圆角+外投影一层，无内阴影），行密度与现状持平
- 这样面试演示时「学生端活泼、管理端专业」的对比本身就是设计能力展示点

### 7.5 第三方/富文本渲染区覆盖清单（批判二-10 对策）

| 渲染区 | 现状来源（开工时实读确认） | 主题化做法 |
|---|---|---|
| AI 回答 Markdown | 前端渲染库 | 容器继承 clay 底色变量；标题/引用/表格色走 token；**逐元素过一遍**防白底白字 |
| 代码块 + 复制按钮 | 渲染库自带样式 | 深色代码底（#2E2A3F）+ 圆角 16px 与整体协调 |
| 管理端图表 | 以实读为准（Chart.js/ECharts） | 调色盘映射六表面色 + coral；禁用默认蓝紫 |
| 表格固定列/分页器 | 页面自带 CSS | clay-light 密度，hover 行高亮用 lavender 10% 透明 |
| 日期/下拉等控件 | 原生或库 | 至少过圆角/边框/焦点环三件套 |

G6 对上述容器逐一断言背景色非透明继承（防「白底白字」这类静默破版）。

### 7.6 版权与离线纪律

- 配色/圆角/阴影参数是**设计参数非素材**，无版权问题；参考站只取气质，**禁复制图片/插画/图标文件**
- 图标：**Phosphor（MIT，6 权重含 fill/duotone）**——2026-09-20 用户批款后调研定稿：圆润实心气质与黏土最贴、SVG 本地 sprite 子集自托管（无 CDN/无图标字体防 FOUT）；备选 Material Symbols Rounded（Apache 2.0）。**emoji 一律禁作图标**（用户批款指令：AI 味太重；与 ui-ux-pro-max 优先级 4 反模式「emoji as icons」同源）
- G8 断网模式下全站可渲染 = 演示现场无网也不翻车

### 7.7 动效与 reduced-motion

- 仅两类动效：hover 抬升 `translateY(-2px)`、active 挤压 `scale(.97)`+阴影减半；140ms ease
- `prefers-reduced-motion: reduce` → 关位移缩放，保留状态色变化（G7 断言）
- **禁**入场动画/滚动视差（静态页 JS 禁碰，且演示求稳）

### 8.2 为什么这套适配 GLM-5.3-Flash（而不是换更强模型）

1. **品味风险被架构消解**：flash 档模型的弱点是审美不稳定与细节遗漏；本管线里风格决策=查表（①）、审美裁决=人挑变体（②）、细节兜底=十道机检门——模型只负责「按冻结令牌写 CSS」，这是快模型最擅长且最不容易翻车的活
2. **速度优势保留**：19 页逐页生成 + 10 门机检的流水线吃生成速度，flash 的 P50 1.88s/TTFT 0.78s（Stage A 实测）撑得起「每页多轮迭代直到门禁绿」
3. **推理型特征无害**：thinking 不可关对纯代码生成不构成负担；约束都写在令牌表和钩子冻结清单里，不依赖模型「自觉」

### 8.3 明确不采用的选项

- **video2code:web-replicate**（复刻参考站）：会**重新生成 DOM**，直接违反三层分离（结构层禁动）——一票否决
- **pick-ui-library**：静态页不引新组件库（引库=新依赖+新 DOM，同上违反冻结）
- **apple-design / emil-design-eng**：动效哲学与黏土的「软弹」路线冲突，不混用

## 十、PARITY 增强（批判二-12 对策）

1. **token 对比扩容**：v1 只比文本节点 → 扩到**属性级文案**（placeholder / title / aria-label / alt / value）+ 内联 JS 里的用户可见字符串（按钮文字/提示语）
2. **截图 diff 三纪律**：①固定演示数据（专用 demo 账号+种子数据，禁随机）②禁动画（注入 `prefers-reduced-motion`）③**遮罩动态区**（时间戳/头像/随机推荐位打码后再 diff）
3. **双向断言**：token 只增不减（文案零丢失）+ 元素计数不变（结构零增删）——单看文本 diff 会漏「按钮整个消失」这类事故

## 十一、公共片段与 React 迁移债（批判二-13/14 对策）

1. **公共层单点维护**：clay 组件类（§7.3 表）全部定义在 theme.css 一处；占位卡/导航/页脚的 HTML 片段规范写成「复制模板+登记」（静态页无构建期组件化，以规范+G3 清单代替）
2. **DOM 钩子冻结清单**：G3 的扫描产物即文档（`docs/dom-hooks-frozen.md`），每页一节——后续维护者知道哪些 class 是 JS 抓手不敢删
3. **迁移对冲三件套**：设计 token 原生 CSS 变量（React 侧复制文件即平移）；`[data-legacy]` 标记所有「仅为兼容旧样式保留」的规则，React 迁移时一次性清除；钩子清单即 React 重构的 DOM 契约

## 十二、权限与演示话术（批判三-17/18 对策）

1. **铁律重申：前端隐藏 ≠ 权限**。内部入口（admin 链接/内部 Tab）按角色分支渲染（现状做法），**禁止**用纯 CSS display:none 藏敏感入口；接口权限一律服务端校验（现状 403 已有），G2 内部可见性项回归
2. **占位四态话术统一组件**：`暂未开放`（后端无规划）/ `即将上线`（契约位已登记）/ `无权限`（角色不足）/ `加载失败`（重试按钮）——四态视觉区分（灰/柠檬/紫/珊瑚边框），杜绝一律「即将上线」的含糊
3. **面试话术**：「课程详情的课件/作业/考试三入口是契约位预埋——data-api 已在登记表绑定端点契约，后端聚合端点建好即接，前端零结构改动」——把占位从「功能缺失」翻转成「架构前瞻」的展示点
