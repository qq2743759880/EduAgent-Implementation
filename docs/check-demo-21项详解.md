# 21 项开机体检单详解（check-demo.mjs）——每项是什么、查什么、坏了怎么拉起

> 「开机」指**项目启动**（后端+前端+数据库都拉起后），不是电脑开机。体检单一条命令：`cd edu-agent && node scripts/check-demo.mjs`，约 2.5 分钟跑完，输出每项 PASS/FAIL/WARN，全绿=可以放心演示。它像飞机起飞前机长的检查单：每一项都对应一个**真实发生过的事故**。

## 总启动顺序（谁先谁后，为什么）

```
① VMware 虚拟机（数据库全家住这里）→ ② Redis 容器 → ③ 后端 8000 → ④ 前端 3000 → ⑤ 体检单
```
数据是地基 → 缓存是水电 → 后端是房子 → 前端是门面 → 体检单是验收。

---

## 逐项详解

### ① Milvus 连通（192.168.85.101:19530）
- **是什么**：Milvus 是「向量数据库」，AI 找资料靠它。住在 VMware 虚拟机里。
- **查什么**：4 毫秒内连上 19530 端口。
- **坏了怎么拉**：开 VMware → 启动「CentOS 7 64 位」（**不是**"的克隆 docker"那台）→ 虚拟机里 docker 会自动带起 Milvus。注意：虚拟机崩溃过（vmware-vmx 进程级 0xc0000005），若 start 后仍未起，用**带界面模式**（GUI）启动而不是 nogui。

### ② Redis 探测
- **是什么**：Redis 管「限流/记忆队列/审批决策/进度存档」，住在 Docker 容器 `prisma-ai-redis-container-1` 里，容器内 6379、宿主机 6377。
- **查什么**：读 `.env` 里的端口（6377）反查容器名，`docker exec ... redis-cli ping` 要回 PONG。
- **⚠ 指令失效真相**：必须带 `docker exec prisma-ai-redis-container-1` 前缀；裸敲 `redis-cli` 会失效（本机没装独立 Redis）。
- **坏了怎么拉**：Docker Desktop → 找到该容器 → Start；Docker 引擎本身僵死时需**手动开 Docker Desktop 等鲸鱼图标变绿**（无人值守唤不醒）。

### ③ MongoDB 连通（192.168.85.101:27017）
- **是什么**：学习行为事件流（看视频/答题的记录）住这里。
- **坏了怎么拉**：同①，虚拟机起来它就起来。

### ④ 后端 8000 /health
- **是什么**：整个系统的心脏（FastAPI）。
- **查什么**：`{"status":"ok","version":"0.3.0"}`。
- **坏了怎么拉**：多数情况**看门狗已自动拉起**（服务化：开机延迟 60s+每 5 分钟巡检，实测约 90-143 秒自愈）。手动：`edu-agent/` 下 PowerShell `Start-Process -FilePath '.\.venv\Scripts\python.exe' -ArgumentList '-m uvicorn app.main:app --port 8000' -WindowStyle Hidden`。

### ⑤ 前端 3000 + 生产形态判别
- **是什么**：门面页面。已用 `next build` 打包成生产形态（`.next-prod/`）。
- **查什么**：login-register.html 返回 200，且开发版探针 `/_next/static/development/_buildManifest.js` 返回 **404**（= 确认跑的是打包后的正式版，不是开发版）。
- **坏了怎么拉**（你今天遇到的 ERR_CONNECTION_REFUSED 就是这个）：`edu-frontend/` 下 bash：
  `(NEXT_PROD_DIST_DIR=.next-prod nohup node node_modules/next/dist/bin/next start -p 3000 > /tmp/next3000.log 2>&1 &)`——**每次重启电脑后要重新执行**（它不随开机自启，TODO：可做成开机任务）。

### ⑥ 登录链路
- **是什么**：用两个真实测试账号（管理员 adm02test / 学生 user000001）各登录一次再取身份信息。
- **查什么**：登录→拿 JWT→/api/auth/me 返回角色，全链路通。
- **坏了**：先看④；若提示 42900 频繁，是连续测太多次被限流（60 秒后再试）。

### ⑦ 关键页 200 × 8
- **是什么**：八个最重要的页面（登录/课程/课程详情/学习/仪表盘/管理页…）逐一访问。
- **坏了**：看⑤。

### ⑧ DEBUG 虚拟管理员探测（WARN=正常）
- **是什么**：安全检查——本机开发模式 DEBUG=true 时，不登录也能看到管理员数据的「后门」是否存在。
- **WARN 含义**：后门确实存在，但这是**本地开发故意的**；正式部署必须 `DEBUG=false`（另有 `--prod-gate` 部署门强制拦截，.env 配错会拒绝部署）。
- **这不是故障**，是体检单在提醒你上线前要关。

### ⑨ 抽验页
- **是什么**：额外抽查一个复杂管理页（用户精炼原型页）。
- **坏了**：看⑤。

### ⑩ 契约对账门（WARN=正常）
- **是什么**：三方对账——前端实际调用的接口 × 后端真实路由 × 冻结的接口契约书。
- **WARN 含义**：还有 66 个后端接口前端尚未接入（属于计划内的迁移残留），**没有「前端调了但后端没有」的断点**。
- **红了才可怕**（说明前端在调用不存在的接口）。

### ⑪ VEC-LOCK embed 一致性
- **是什么**：检查向量库 3388 条数据的「指纹」——所有向量必须出自同一个 AI 编码模型（BGE-M3）。
- **为什么重要**：不同模型生成的向量是「不同语言」，混了就查不准（曾发生过真实事故）。
- **坏了**：查 `EMBED_BACKEND=cuda` 配置是否被动过。

### ⑬ MCP 三态门
- **是什么**：AI 的 17 个工具，逐一核对「声称有的能力」和「真实接线的能力」一致，参数脱敏。
- **坏了**：看后端日志的 MCP 加载段。

### ⑫ HITL 真实性
- **是什么**：AI 执行危险操作前的「人工确认卡」真的能拦住并续流（历史 bug：确认后流断掉）。
- **这次显示「跳过」**：本轮对话模型没触发危险工具，单测已覆盖——正常。

### ⑭ 内部可见性
- **是什么**：学生身份检索 5 次 → **0 条内部文档**；管理员检索 → 24 条。证明隔离有效。

### ⑮ Redis 部署对账
- **是什么**：配置文件写的端口（6377）= 容器实际映射端口（6377）。
- **历史事故**：容器换名后配置还指着旧端口，导致所有依赖 Redis 的功能静默降级。

### ⑯ 8000 lifecycle 健壮性
- **是什么**：连续启停后端 5 次，不崩溃不报错（历史 bug：关闭时的竞态崩溃）。

### ⑰ MCP 跨权限门对账
- **是什么**：按管理员/学生/访客三种身份核对每个工具的可用性矩阵。

### ⑱ febe root path 闭环
- **是什么**：运维类路径（/health、/metrics）都被契约正确登记。

### ⑲ VEC-LOCK 守门（12 维，耗时最长 ~2 分钟）
- **是什么**：向量质量的 12 个维度全面体检（模型/归一化/池化/截断/黄金集…）。

### ⑳ OTLP 链路健康
- **是什么**：可观测性（监控数据上报）管道。
- **state=disabled**：管道已建成，但还没接真实的监控后端——**诚实显示未启用**，不是故障。

### ㉒ object_key 复用历史审计（WARN=正常）
- **是什么**：检查上传文件的存储键是否有历史复用（曾经撞名覆盖过）。
- **WARN 含义**：历史上有 55 个键复用过（**无法回填的过去**），新上传已用新规则防护。

## 三个 WARN 的正确读法
⑧（上线前关 DEBUG）、⑩（计划内迁移残留）、㉒（历史已防护）——**都不阻碍演示**。判断标准看最后一行：`演示环境就绪`。
