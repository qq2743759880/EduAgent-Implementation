# 面试演示手册（小学生也能照做版）

> 使用方法：从头到尾按顺序做，**每一节=「你要做什么」+「屏幕上会出现什么」+「你要对面试官说什么（原话照念）」+「面试官可能追问，怎么答」**。全程约 20 分钟。演示前一天晚上先把「第 0 步 演示前检查」做一遍。

---

## 第 0 步：演示前一晚的检查（5 分钟）

**做什么**：
1. 开 VMware，启动「CentOS 7 64 位」那台虚拟机（不是"的克隆 docker"那台），等 2 分钟
2. 开 Docker Desktop，等鲸鱼图标变绿，确认 `prisma-ai-redis-container-1` 容器是绿色 Running
3. 打开两个黑色终端窗口，分别执行：
   - 窗口 A（后端）：`cd E:\stu\project\stu\EduAgent实施手册\edu-agent`，然后 PowerShell 里执行 `Start-Process -FilePath '.\.venv\Scripts\python.exe' -ArgumentList '-m uvicorn app.main:app --port 8000' -WindowStyle Hidden`
   - 窗口 B（前端）：`cd E:\stu\project\stu\EduAgent实施手册\edu-frontend`，然后 `(NEXT_PROD_DIST_DIR=.next-prod nohup node node_modules/next/dist/bin/next start -p 3000 > /tmp/next3000.log 2>&1 &)`
4. 体检：`cd edu-agent` 然后 `node scripts/check-demo.mjs`，等 2.5 分钟
5. **看到最后一行「演示环境就绪」才去睡觉**；有红色就按《21 项详解》文档排查

**给面试官的第一句话（开场）**：
> "这是一个教育平台的 AI 助手系统。我按数据流的顺序演示：用户看到的前端 → 后端大脑 → AI 怎么找资料 → 数据怎么存 → 工程怎么保证质量。"

## 第 1 站：前端页面（1 分钟）

**做什么**：浏览器开 `http://127.0.0.1:3000/login-register.html`

**屏幕会出现**：彩色登录页

**照念**：
> "前端用 Next.js。这里有个细节——现在跑的是**打包后的正式版**，不是开发版。"

**操作**：新开一个标签页访问 `http://127.0.0.1:3000/_next/static/development/_buildManifest.js`

**屏幕会出现**：**404 页面**

**照念**：
> "看到 404 就对了——开发版才会存在这个文件。生产版本没有它。这是判断前端是正式版还是开发版的探针，我们的自动体检单用的就是这一招。"

**追问「为什么搞两套前端」**：
> "这是渐进迁移：旧静态页保证演示永远可用，新功能只往 Next.js 里写，成熟一个域切换一个域。好处是随时可以回滚。"

---

## 第 2 站：后端接口说明书（2 分钟）

**做什么**：开 `http://127.0.0.1:8000/docs`

**屏幕会出现**：一个可以点的接口列表（Swagger 文档页）

**操作**：在搜索框输入 `kg`，找到 `GET /api/kg/course/{course_id}/path`，点开 → Try it out → course_id 填 `1` → from 填 `KP-PY-VAR` → to 填 `KP-PY-SQL` → Execute

**屏幕会出现**：hops=5 的路径 JSON

**照念**：
> "后端是 FastAPI，210 多个接口，每个都有自动生成的文档。刚才这个接口是知识图谱学习路径——从'变量'这个知识点到'SQL'，系统自动算出 5 步的学习路线。注意返回格式统一是 code/message/data 三件套。"

**追问「出错了怎么返回」**：
> "错误也是统一格式。比如把 course_id 改成 999999 再 Execute——看到 code 40460 了吗？每个错误码都有编号，前端据此做友好提示。"

## 第 3 站：AI 检索的核心——向量数据库 Milvus（4 分钟，最重要）

**做什么**：终端里执行：
```
cd edu-agent
.venv\Scripts\python.exe scripts\eval\milvus_count_probe.py --rounds 1
```

**屏幕会出现**：一段 JSON，里面有 count_star、enumerate 等数字

**照念**：
> "AI 回答问题前要先找资料，靠的是向量数据库 Milvus。资料被 AI 模型转成一串数字（向量），意思相近的资料向量也相近。刚才这个探针在做数据体检——它用两种方法数库里的数据，数字能对上说明数据没坏。"

**然后做什么**：开另一个终端实时看日志（如果日志文件路径找不到就跳过，直接指着上一条说）：
```
说明："每次用户提问，系统会同时用两种方法找：一种像'按意思找'（神经网络），一种像'按关键词找'（全文检索），找到的 150 条候选再融合排序，最后精挑 5 条给 AI 看着回答。"
```

**关键数字（可以写在手心）**：
> "检索准确率 98.4%——而且我们换了问法反复验证过，是真的会，不是靠原文匹配的巧合。"

**追问「怎么证明 98% 是真的」**：
> "我们有三把尺子：第一把尺子旧了（出题方式和目标不匹配，只量出 7.8%）；换第二把尺子量出 98.4%；最狠的是第三把——把考题全部换成不同说法（和原文字面重叠只剩 27%），还是 98.4%。三把尺子交叉，证明这是真实能力。"

## 第 4 站：知识图谱 Neo4j（3 分钟）

**做什么**：浏览器开第 2 站那个路径接口再指一遍，然后说图。有条件的话开 Neo4j Browser（`http://192.168.85.101:7474`）输入：
```
MATCH p=()-[r:PREREQUISITE]->() RETURN p LIMIT 25
```
（如果浏览器打不开就直接讲，跳过操作）

**屏幕会出现**：一张网状的图，圆点（知识点）之间有箭头（先修关系）

**照念**：
> "这是 Neo4j 知识图谱。课程知识点之间有'先学哪个才能学哪个'的关系（就像先学加法才能学乘法）。第 2 站那个 5 步学习路线就是在这张图上算出来的。系统还会检查图里有没有'死循环'（A 依赖 B、B 又依赖 A），有就报错而不是卡死。"

**追问「为什么这东西要单独用图数据库」**：
> "查'往前数 5 层依赖'这种问题，图数据库一句话；用普通数据库要写递归查询，数据一大就慢。"

---

## 第 5 站：MongoDB 和 Redis（2 分钟）

**做什么**：终端执行（Redis 交互演示）：
```
docker exec prisma-ai-redis-container-1 redis-cli keys rl:*
```

**屏幕会出现**：一些限流键名（或空列表）

**照念**：
> "Redis 是'快取小抽屉'，管五件事：防止有人疯狂刷接口（限流）、登录令牌刷新、AI 对话进度存档、危险操作的确认决策、AI 的记忆队列。刚才列出的 rl 开头的键就是限流记录。"

**Mongo 部分照念**：
> "MongoDB 存'学习行为流水'——每个学生每次看视频、答题，都记一条。这些记录写得多、格式常变，放 MongoDB 合适；但订单、钱相关的还是放 MySQL 保证事务一致。两边的数字有对账脚本，一致率 100%。"

**追问「为什么不全用 MySQL」**：
> "让合适的数据库干合适的活：高写入流水进 Mongo，事务进 MySQL，检索进 Milvus，关系进 Neo4j——每个都因为对应场景的物理特性。"

---

## 第 6 站：AI 对话 + 安全确认卡（4 分钟，最出彩）

**做什么**：浏览器登录（adm02test / Test@123456）→ 进 AI 助手聊天页 → 输入：
```
帮我把一份新的课程文档导入知识库
```

**屏幕会出现**：AI 回答中出现一张**确认卡片**（待确认操作：知识导入，带风险级别）

**照念**：
> "AI 想执行'写类'危险操作时，不会直接干，而是弹出确认卡等人点头。这是四道防线里的'人工确认'。"

**操作**：先点**拒绝** → AI 回复已取消；再发一次同样消息 → 这次点**确认** → 工具真的执行

**照念**：
> "拒绝就取消，确认才执行，全程有审计记录。四道防线是：权限门（默认拒绝一切没授权的）→ 这里的人工确认 → 参数严格校验 → 事后审计。我们还做过'坏人测试'——冒充学生诱导 AI 执行危险操作，零成功。"

**追问「AI 被恶意指令骗了怎么办」**：
> "授权不是 AI 说了算，是服务端的权限矩阵说了算——AI 只能'申请'，批不批在代码里写死，模型改不了。"

## 第 7 站：自动化体检 + 自动复活（3 分钟，压轴）

**做什么**：终端跑全量测试（这一步可以提前开始跑，讲第 3 站时就让它后台跑着）：
```
cd edu-agent
.venv\Scripts\python.exe -m pytest tests/ -q
```

**屏幕会出现**：一排排小绿点，最后 `1798 passed, 57 skipped`（约 7 分钟）

**照念**：
> "这是 1798 个自动化测试，覆盖登录、订单、检索、权限……每次改代码都全量跑一遍，零失败才准合并。旁边还有 21 项开机体检（可以指第 0 步的输出），每一项背后都是一个真实发生过的事故。"

**复活演示（可选，刺激）**：任务管理器找到 8000 端口的 python 进程（用 `netstat -ano | findstr :8000` 找 PID）→ 结束它 → 等约 90-143 秒

**屏幕会出现**：服务自己回来了（watchdog 每 5 分钟巡检自动拉起）

**照念**：
> "后端被杀死了也会自动复活——看门狗程序挂了 Windows 任务计划，每 5 分钟检查一次，发现死了就拉起来。这套自愈经历过真实崩溃验证。"

## 急救卡（演示翻车时）

| 症状 | 急救 |
|---|---|
| 前端打不开（ERR_CONNECTION_REFUSED） | 重跑第 0 步窗口 B 命令 |
| 后端 /health 不通 | 等看门狗 2 分钟；或重跑窗口 A |
| Milvus/Mongo 不通 | 虚拟机没开或开错（要用"CentOS 7 64 位"不是克隆） |
| 检索/图谱接口 50301 | 依赖组件断了，重启后端 |
| 登录 42900 | 测太频繁，等 60 秒 |
| 演示机死机 | 所有数据可重建（备份在），重启后按第 0 步来 |
