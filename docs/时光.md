## 四、工具 B：course_create（管理端建课，高危，强制 HITL）

### B1. executor 注册

```python
_BUILTIN_TOOLS["course_create"] = _BuiltinTool(
    name="course_create",
    description="创建课程系列（管理员操作，需人工确认）。参数：title(str)、series_code(str)、"
                "modules(list[str]，可选)。",
    handler=_tool_course_create,
    arg_schema={
        "type": "object",
        "properties": {
            "title": {"type": "string", "minLength": 1},
            "series_code": {"type": "string", "pattern": "^[a-z0-9_]+$"},
            "modules": {"type": "array", "items": {"type": "string"}},
        },
        "required": ["title", "series_code"],
        "additionalProperties": False,
    },
)

async def _tool_course_create(args: dict, ctx: ToolContext) -> ToolResult:
    """直调 course_admin service；调用前提=ctx['hitl_confirmed'] 为 True
    （由 resume confirm 流置位，见 B3——未经确认的调用在 executor 侧直接拒，双保险）。"""
    if not ctx.get("hitl_confirmed"):
        return ToolResult(ok=False, error="42201", message="高危工具未确认，拒绝执行")
    result = await course_admin_service.create_series(
        operator_id=ctx.user_id, title=args["title"],
        series_code=args["series_code"], modules=args.get("modules", []))
    return ToolResult(ok=True, data=result, summary=f"课程已创建：{result['series_code']}")
```

### B2. 权限矩阵

TOOL_CLASS_MAP["course_create"] = "admin_write"
# 矩阵：admin=allow / manager=deny(默认) / student=deny / teacher=deny / guest=deny

### B3. HITL 链路（**关键改造：单一事实源**）

现状缺陷：`_hitl_risk_level` 读的是 CONTRACT_PENDING_* 挂起集合——工具正式上线后名字挪走，HITL 反而失明。改造：

```python
# langgraph_agent.py / graph_stream.py 消费侧统一改为：
def _hitl_risk_level(tool_name: str) -> str | None:
    """写类风险分级：从 TOOL_CLASS_MAP 的类别直接推导（单一事实源）。
    admin_write/course_write → "high"；user_write → None（不弹卡）。"""
    cls = TOOL_CLASS_MAP.get(_norm(tool_name))
    if cls in ("admin_write", "course_write"):
        return "high"
    return None
```

resume 流置位：confirm 后 `ctx["hitl_confirmed"]=True`（tool_calling 的 on_write_class_pending 段，一次注入），reject 则不执行并回「已取消」。

### B5. 联调脚本（curl 序列）

```bash
ATOKEN=$(curl -s -X POST http://127.0.0.1:9988/api/auth/login ... adm02test ...)   # admin 登录
SID2=$(curl -s -X POST http://127.0.0.1:9988/api/chat/sessions -H "Authorization: Bearer $ATOKEN" ...)
# ① 流式触发（期望：出现 event: pending_confirm 帧，五字段齐）
curl -N -X POST http://127.0.0.1:9988/api/chat/stream -H "Authorization: Bearer $ATOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"帮我创建一门新课，标题'趣味算法入门'，系列码 fun_algo_101\",\"session_id\":\"$SID2\",\"stream\":true}"
# ② confirm（thread_id 取自上一步帧）
curl -s -X POST http://127.0.0.1:9988/api/chat/resume -H "Authorization: Bearer $ATOKEN" \
  -H "Content-Type: application/json" -d "{\"session_id\":\"$SID2\",\"thread_id\":\"<帧中thread_id>\",\"action\":\"confirm\"}"
# 期望：续流完成 + answer 含「课程已创建」
# ③ 数据侧：GET /api/admin/courses?search=fun_algo_101 → 存在（验收后删除测试课）
# ④ reject 路：再来一轮，action=reject → answer=已取消，DB 无新课程
```
