## 第 0 章：演示前 3 分钟（开机清单）

### 0.1 确认服务都在岗

打开一个 **PowerShell** 窗口，把下面整段复制进去按回车：

```powershell
"9988 后端",9988 | Out-Null
foreach ($t in @(@("后端",9988), @("前端",3322), @("MySQL",3306), @("Redis",6377))) {
  $ok = Test-NetConnection -ComputerName 127.0.0.1 -Port $t[1] -InformationLevel Quiet -WarningAction SilentlyContinue
  if ($ok) { Write-Host "✅ $($t[0]) 在岗" -ForegroundColor Green } else { Write-Host "❌ $($t[0]) 没启动！" -ForegroundColor Red }
}
```

**期望输出：4 个 ✅**。哪个是 ❌ 就看 0.2。

| 哪个红了 | 补救动作 |

| MySQL / Redis | MySQL 是 Windows 服务自启；Redis 在 Docker 里：开 **Docker Desktop**，找到 `prisma-ai-redis-container-1` 点 ▶ Start |

**最终自检**：浏览器打开 `http://127.0.0.1:9988/health` —— 看到 `{"status":"ok"...}` 就绪。

> ✅ **跨会话记忆状态（2026-09-24 TA7-D3 已修复）**：跨会话召回恢复正常，本步**可当场演示**，不必改口。
> 根因与修法：BGE-M3 走 fp16（`EMBED_DEVICE=cuda`）时长时间存活的服务进程会**间歇性**产出
> NaN/±Inf 稠密向量（实测：同一文本在全新进程 100% 有限，在运行态进程 10/10 次非有限）→
> 该向量被 Milvus 拒收（`code=65535, value 'NaN' is not a number or infinity`），
> 记忆只落到进程内档；而读取恒先问 Milvus 且"空结果无异常"时直接返回 → **跨会话召回恒空**。
> TA7 在记忆向量域收口：① 源头防护（非有限 → 整批降级确定性哈希向量并如实标注）
> ② 入库前清洗（含调用方显式传的 vector）③ 档位对称（Milvus 命中不足时合并进程内档）。
> 实测：会话 A 说名字 → 新会话问名字 → **答对**（证据 `.ai-hub/plans/artifacts/dispatch/ta7/ta7_accept_result.json`）。
> ⚠️ 唯一注意项：Milvus 有约 3s 的「写后读可见窗口」——会话 A 说完名字后**正常停顿再新建会话**即可（别 0 秒手速连点）。

## 第 2.6 章：黄条演示站（AI 谎报"已完成"被机器打标）

> 一句话台词：「AI 说'已收藏'，可工具根本没执行——系统会自己把这轮回执标成不可信，不让它混过去。」

> ✅ **当前状态（2026-09-24 TA7-D1 已修复，流式界面可当场演示）**：黄条已在默认流式界面 `chat.html` 恢复触发，
> **实测连续 3 次 3/3 出现**（截图 `test-reports/ta7/shots/b11-ta7-r1.png` ~ `r3.png`，互异哈希）。
>
> 根因（与 TC2/TC3 的诊断不同，以 TA7 返工单实测为准）：内置工具 `favorite_add` 的**业务失败**
> （课程不存在 → `{"ok": false, "code": "40400", ...}`）是**返回结构化 JSON**而非抛异常，
> 而内置执行路径只看"handler 有没有抛"→ 一律映射 `status=SUCCESS`：调用日志落 `SUCCESS`、
> SSE `mcp_tool_calls[].status="success"` → 护栏判"有成功凭据" → **黄条永不触发**。
> 修法 = **凭据语义真化**：业务失败（`ok:false` / 非 0 code）一律映射 `status=ERROR`，
> 并识别为**确定性终态**（不重试、不出人工指南）；护栏本身**零改动**，改的是它读到的凭据。
> 附修 D2：按名解析整串零命中时退化为"最接近候选"（`status=fuzzy`，仅建议、一律 need_clarify）。

**稳定触发话术（原句，逐字照抄；流式 `chat.html` 已实测 3/3 可复现）**：
```
帮我把《Python 入门》这门课加入我的收藏，并说明你调用了哪个工具、结果如何。
```
> 为什么加后半句：本库**不存在**《Python 入门》，工具必然业务失败（`40400`）；
> 让 AI"说明调用了哪个工具"→ 答案里出现写类工具名 `favorite_add` → 命中护栏触发路径 ②，
> 触发稳定、与模型措辞无关。台词：「这句提示是机器加的——答案声称调用了写类工具，
> 但工具调用记录里没有 success 凭据，护栏据实把该轮回执标成不可信。」
>
> 备选话术（同源，走触发路径 ① **完成词**——模型有时会直接写"收藏操作已提交成功"，
> 含完成词「已提交」即命中；TA7 实测两种措辞都能触发）：
> ```
> 帮我把《Python 入门》这门课收藏起来，并简短说明你会怎么处理。
> ```

**② 流式界面演示（当前可用，已实测 3/3）**：
1. 学生端打开 `http://127.0.0.1:3322/chat.html`（顶部导航「AI 学习助手」）。
2. 把上面原句粘进底部输入框，按 Enter 或点发送。

   （截图证据：`test-reports/ta7/shots/b11-ta7-r1.png` / `r2.png` / `r3.png`，
   三轮哈希互异 = 三次真实独立触发，不是同一张图复用；判定文本由 CDP 从 DOM 读出：
   `role="alert"` 文本含「未实际执行」。）

## 第 2.7 章：OTel 演示站（一次提问 → Jaeger 里看到分层瀑布）

> 一句话台词：「一次提问在我这里不是一个黑盒——检索、调模型、工具调用各花了多久，Jaeger 里是一条能点开的瀑布图。哪段慢，图上直接指出来。」

**① 起容器（演示前一次性，约 10 秒）**

```bash
docker run -d --name eduagent-jaeger \
  -e COLLECTOR_OTLP_ENABLED=true \
  -p 127.0.0.1:14318:4318 \
  -p 127.0.0.1:16686:16686 \
  docker.1ms.run/jaegertracing/all-in-one:latest
```
> ⚠️ **为什么是 14318 而不是 4318**：本机 4318 已被别的容器（openclaw 的 otel collector）占用，所以 Jaeger 的 OTLP HTTP 端口映射到 **14318**，UI 仍在 **16686**。容器已存在时无需重复起，用 `docker start eduagent-jaeger` 即可。
>
> 内存存储，**重启即清空**——所以演示顺序是「先起容器 → 再发问 → 再看图」，不要反过来。

**② 确认后端已连上（看启动日志一行）**

后端启动时会打一行真探活结果：
```
[OTLP-HTTP] 真探活通过 endpoint=http://127.0.0.1:14318/v1/traces status=200 6ms ✔
```
> 这条是**真发了一个 OTLP POST 拿到 2xx**，不是纯 TCP 握手——「绿 = 真通」。
> 没看到这行 → 检查 `edu-agent/.env` 里 `OTEL_EXPORTER_OTLP_ENDPOINT` 是否**带 `/v1/traces` 后缀**（漏后缀会 POST 裸根，Jaeger 返回 404）。

| 追问 | 答 |
|---|---|
| "探活绿就代表通吗？" | 我一开始就是纯 TCP 握手探活，**恒绿**——但导出其实 404。现在改成真发 OTLP POST，2xx 才算绿；项目里记了一条通用教训叫「探活绿 ≠ 链路通」。 |
| "为什么用 SimpleSpanProcessor 不用 Batch？" | 同步导出，`span.end()` 当帧就 POST，发问完立刻能在 Jaeger 查到；Batch 有 500ms 调度延迟，且进程收尾时会丢尾帧（**实测丢过 3 个子 span，只剩 root**）。量大可切 `OTEL_TRACING_PROCESSOR=batch`。 |
