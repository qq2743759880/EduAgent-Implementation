## 一、结论先行（编排者速取）

- **React 应用已不是"从零建页"，而是"契约对齐 + 清 MOCK + 补真实交互"**。全部 23 个 page.tsx 路由均已上真实后端；契约缺口处统一走「实披露占位 / RequestedState / ErrorState」，**无一页是整页 MOCK**。

- **硬前置（不可违）**：C-A（task114 响应壳统一）+ C-B（task115 分页统一）**冻结验收前，React 页不得开始契约对齐**。本单所有"对齐"步均排在 C-A/C-B 之后。

- **管理端不是 \~14 页（旧定义）**：实际 `(admin)/admin/` 下仅 **8 个 page.tsx 路由**（dashboard / courses / courses/\[seriesId] / questions / questions/\[id] / users / rag / mcp）。三批按"用户端 2 批 + 管理端 1 批"而非"管理端独 3 批"编排。

- **三条后端域缺口需上浮用户拍板**（见 §四）：公告(notice)、报表(热门课程榜/运营聚合 `/api/admin/trade/overview`)、课程评价（契约②无评价端点）；以及 trade/market/after\_sales 的**独立订单/支付/退款/工单页面在 React 未建**（客户端已封装但无 page 消费）。

- **最值得先做的一个补位**：`/admin/rag` 缺「知识文件上传 Tab」——task61 已在 fe-html 静态 `admin-rag.html` 落地（pdfplumber 已补装），React 版仍只有 集合/预设/检索/审计 四区，`uploadKnowledgeFiles / uploadMyKnowledgeFiles` 封装**零页面消费**。
