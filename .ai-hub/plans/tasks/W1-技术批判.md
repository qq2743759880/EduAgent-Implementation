# W1 里程碑技术批判（task101~110 批次，2026-09-02）

> 批判者：编排者（ZCode）。人设：以同类顶级竞品为唯一批判根据，故意挑刺。每条含问题/竞品对标/证据/差距/优化方向/最小验证。

## C1 401处理缺静默刷新重放与主流HTTP客户端生态有代差

- **问题**：task101 的 edu-api.js 在 401 时无条件清 token 跳登录。但后端已提供 `POST /api/auth/refresh`（auth/router.py:115），前端完全未消费——access token 过期即打断用户当前操作跳登录页。
- **竞品对标**：axios 拦截器标准做法是 401 → 用 refresh token 静默换新 → 重放原请求 → 仍失败才跳登录（https://axios-http.com/docs/interceptors，访问日期 2026-09-02）；TanStack Query 生态同理（query 配合 retry/refresh token rotation）。
- **差距**：用户体验上"每次过期都被踢回登录页"是竞品十年前就解决的痛点；多标签页并发 401 还会重复跳转。
- **优化方向**：在 edu-api.js 加单飞（single-flight）refresh：401 → 持 refresh_token 换新 → 重放一次 → 失败才走登出。属契约内消费（refresh 端点已冻结），无后端改动。
- **最小验证**：把测试账号 access token 的过期人为调短，操作中被 401 时自动恢复而不跳登录。
- **收益/成本**：UX 显著提升 / 前端 ~40 行；登记 tracker，建议 task122 或独立小任务承接。

## C2 管理端守卫是8份内联拷贝与集中式路由守卫竞品模式相悖

- **问题**：task109 的三段守卫内联复制进 8 个 admin 页。已收敛数据注入为 bootAdmin，但守卫本体仍是 8 份拷贝——下次改鉴权逻辑（如加 teacher 角色）要改 8 处，漂移风险正是 task105 之前"页面各自为政"的老病根。
- **竞品对标**：React Router loader / TanStack Router beforeLoad 集中守卫（https://reactrouter.com/en/main/start/tutorial，访问日期 2026-09-02）；传统多页应用等效物是单一共享 JS 模块（如 edu-guard.js）+ 一行引入。
- **差距**：静态站也能单点化（`<script src="/edu-guard.js">` 先行），竞品无此问题。
- **优化方向**：task122 卫生包把守卫片段抽成 edu-guard.js（与 task110 的 scan-deadlinks.mjs 一样属"工具资产化"），8 页改一行引入。
- **最小验证**：抽离后 grep 8 页守卫内联代码=0、edu-guard.js 引用=8；三角色行为回归。
- **收益/成本**：消除 8 份拷贝漂移风险 / 半小时。

## C3 死链扫描是一次性脚本未CI化且变量拼接静态盲区被实测证伪

- **问题**：task110 交付的 scan-deadlinks.mjs 是好的起点，但（a）不在任何回归门里，下次改导航不会自动跑；（b）编排者验收时自写扫描器曾把 community-post.html 误判为孤立页——变量拼接跳转（`"/x.html?"+id`）静态可见性有限，纯静态扫描存在假阴性。
- **竞品对标**：lychee（https://github.com/lycheeverse/lychee，访问日期 2026-09-02）支持并发+缓存+ exclude 规则并可进 CI；对 SPA 路由则用 Playwright 类运行时巡检——本项目运行时巡检被禁（AGENTS.md 教训②），静态扫描+人工走查是现实约束下的组合。
- **差距**：竞品是门禁，我们是事后工具；静态盲区无运行时兜底。
- **优化方向**：把 scan-deadlinks.mjs 挂进 W4 里程碑检查单（task123），并在 L4 全量回归跑一次；接受"静态扫描+变量拼接人工走查"的口径写进工具头注释。
- **最小验证**：在 task123 检查单里作为固定条目跑通一次。
- **收益/成本**：防回归 / 极小。

## C4 注册后两步式登录是契约约束下的次优UX

- **问题**：后端 `POST /api/auth/register` 返回 201 不含 token，前端只能"预填账号→再登录"两步（task108 选择了改动最小方案，正确）。
- **竞品对标**：主流注册即登录（回到首页无缝体验）；OWASP 会话管理章节允许注册后直接建立会话（https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html，访问日期 2026-09-02）。
- **差距**：多一步登录，转化漏斗多一跳。
- **优化方向**：属后端契约增强（register 返回 token 或 201+自动登录端点），登记 tracker 作为低优先级契约增强项，随 C-A（task114）评估顺带，不单独派任务。
- **最小验证**：若纳入 C-A，curl register 响应含 access_token 即验收。
