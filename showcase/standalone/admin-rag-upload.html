这个 tab 做什么 · 上传
把课程资料（.md/.txt/.markdown/.pdf/.docx）丢进来，系统会切分成知识块并写入向量库，供 AI 对话检索引用。 下方「导入任务」跟踪每批文件的处理进度，轮询到 完成 才算真正入库。
调什么：选文件 → 开始上传。
调完看什么：任务状态变成绿色「完成」，且「集合健康」里的向量行数变大。
失败怎么办
状态是红色「失败」时，看同行的「错误明细」列：常见是 PDF 解析缺依赖或文件格式异常。 前端在选文件阶段就会拦掉非法扩展名 / 超 200MB / 超 50 个。
示例：上传 课程大纲.docx 后任务显示 完成、分块进度 100% → 表示可被检索到。

知识库上传 · 导入任务 · 分区管理
这个 tab 做什么 · 集合
查看知识库有哪几个集合（collection）及其分区的行数与健康状态，并在这里发起索引重建。 集合是向量的物理容器，AI 检索时按集合+分区过滤。
调什么：选集合/分区 + 模式（incremental 补漏 / full 清空重建）。
调完看什么：列表里该行 status 回到 ready、最近重建 时间刷新。
什么时候用重建
上传后检索不到内容、或删过向量感觉行数对不上时，用 incremental 补缺失索引； 怀疑索引整体损坏才用 full（会清空重来，耗时最长，有二次确认）。
示例：新传 10 份文档后检索命中率偏低 → 选 incremental 重建，看行数是否补上。

这个 tab 做什么 · 调参
把一套检索参数存成预设，供高级检索或 AI 对话按名字复用，避免每次手填。 核心四个旋钮：top_k（召回条数）、final_max_k（最终喂给模型条数）、 cutoff（相似度丢弃阈值）、rrf_k（多路融合平滑）。
调什么：改上面四个数 + HyDE / 图谱开关，填名称后「创建预设」。
调完看什么：列表出现该行；再去「高级检索」选这个预设跑一次，看命中条数与 score 变化。
怎么调不踩坑
想召回更全→ 调大 top_k；想让答案更聚焦→ 调小 final_max_k 或调高 cutoff； 改完一定用「高级检索」对比同一条 query 的前后命中，确认真的变好再设为默认。
示例：「备考-高召回」＝ top_k 40 / final_max_k 8 / cutoff 0.3，适合问法模糊时。

新建预设

POST /api/admin/rag/presets（ParamPresetCreate）
创建后可在「高级检索」下拉里选到该预设。
这个 tab 做什么 · 审计日志
落库的每一次检索调用流水，用来复盘「AI 为什么这么答」：谁问的（角色）、召回多少条、 最终用了几条、走的哪个模型、延迟多少、是否降级。
调什么：切每页条数 / 翻页（只读，不改数据）。
调完看什么：某条 query 的召回/最终 比例异常（如 20/0）或「降级/错误」列非空 → 说明检索侧有问题。
和「调参」怎么配合
调完预设后在这里按时间倒序找刚跑的 query，对比调整前后的 召回/最终 与 延迟， 用真实流水判断这次调参是有效还是白改。延迟明显变大往往意味着 top_k 开太高。
示例：调高 top_k 后延迟从 300ms 涨到 1.2s、最终条数没变 → 该旋钮对当前库没收益，回退。

这个 tab 做什么 · 高级检索
以管理员身份直连全库跑一次检索，看到原始召回结果（含 score / 来源文件 / 命中通道）。 这是验证「调参」和「上传」是否生效的唯一直接手段——AI 对话里只能看到最终答案，看不到召回明细。
调什么：输入查询词，可选用某个预设，点「检索」。
调完看什么：命中条数与 score 排序；via 显示命中了哪条通道（向量/关键词/图谱）。
结果怎么读
「无结果（final_count=0）」＝ 库里有内容但都被 cutoff 丢掉了，回「调参」把阈值调低再试； 一直查不到任何东西，先回「上传」确认文件是否真的导入成功。
示例：查「向量检索 三通道」→ 命中 6 条、score 0.72 起 → 说明该主题资料已入库且可检索。
